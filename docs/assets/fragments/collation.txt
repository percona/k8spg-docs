Scan for indexes that rely on collations other than `C` or `POSIX` and whose collations were provided by the operating system (`c`) or dynamic libraries (`d`). [Connect to PostgreSQL](connect.md) with the privileges of the superuser or the database owner and run the following query:

```sql
SELECT DISTINCT
    indrelid::regclass::text,
    indexrelid::regclass::text,
    collname,
    pg_get_indexdef(indexrelid)
FROM (
    SELECT
        indexrelid,
        indrelid,
        indcollation[i] coll
    FROM
        pg_index,
        generate_subscripts(indcollation, 1) g(i)
) s
JOIN pg_collation c ON coll = c.oid
WHERE
    collprovider IN ('d', 'c')
    AND collname NOT IN ('C', 'POSIX');
```

If you see affected indexes, find the databases whose collation 
version changed:

```sql
SELECT datname, datlocprovider, datcollate, datcollversion
FROM pg_database;
```

??? example "Sample output"

    ```{.text .no-copy}
    datname   | datlocprovider | datcollate  | datcollversion
    ----------+----------------+-------------+----------------
    postgres  | c              | en_US.utf-8 | 2.28
    template1 | c              | en_US.utf-8 | 2.28
    template0 | c              | en_US.utf-8 |
    cluster1  | c              | en_US.utf-8 | 2.28
    ```

Rebuild affected indexes first. [REINDEX](https://www.postgresql.org/docs/current/sql-reindex.html) updates the index using the current collation rules:

```sql
REINDEX INDEX CONCURRENTLY <index_name>;
```

Repeat for every affected index, or rebuild all indexes in a database with `REINDEX DATABASE <database_name>;`.

A `UNIQUE` index or a primary key can fail to rebuild because the old sort order let duplicate keys in. Remove the duplicate rows and rebuild the index again.

Next, check the objects that depend on the sort order. `REINDEX` doesn't fix them:

- Partitions with text range bounds. Move the rows that sit in the wrong partition.
- `CHECK` constraints on text values. Validate them again.
- Stored generated columns. Recompute the values.
- Materialized views. Run `REFRESH MATERIALIZED VIEW <view_name>;`.

Then refresh collation metadata. `ALTER DATABASE ... REFRESH COLLATION VERSION` only updates PostgreSQL's recorded metadata. It does not rebuild indexes created using the previous collation rules. Run it last, after the rebuilds:

```sql
ALTER DATABASE cluster1 REFRESH COLLATION VERSION;
```

This command requires the privileges of a superuser or a database owner.
**Repeat for every affected database.**

Finally, update the planner statistics:

```sql
ANALYZE;
```
